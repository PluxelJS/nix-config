# Nix Home Manager Layout

This flake owns the user-space environment for `ahdg` on Arch. It is focused on
shell tooling plus the desktop-adjacent pieces that benefit from being
reproducible in Home Manager:

- `zsh`
- `starship`
- `atuin`
- `pay-respects`
- `git` and `delta`
- `gh`
- `ragenix`
- `fzf`, `fzf-tab`, `zoxide`, `mise`
- `fastfetch`
- `ghostty`
- `mango` config and helper scripts
- `fcitx5` config, themes, and Rime payloads
- `fontconfig`
- `gtk-2.0`
- GTK and Plasma theme assets
- Flatpak global host integration
- XDG defaults and portal policy

System-level session pieces such as the compositor, login manager, and other
machine-wide services still live outside this flake.

## Ownership Summary

This flake is now the canonical owner of:

- shell behavior: `zsh` init order, aliases, history, completions, `atuin`,
  `pay-respects`, `fzf`, `fzf-tab`, `zoxide`, `mise`, `starship`
- shell tools and CLI packages installed through Home Manager:
  `bat`, `delta`, `eza`, `fd`, `fzf`, `gh`, `git`, `mise`, `ragenix`,
  `ripgrep`, `starship`, `zoxide`
- GitHub CLI config; auth workflow guidance lives in `docs/gh-auth.md`
- terminal experience: `ghostty`, its config, terminfo, nixGL wrapper, and the
  writable DMS color overlay seed
- desktop shell-adjacent tools: `fastfetch`
- MangoWC user config, keybinds, rules, and helper scripts under
  `~/.config/mango`
- fonts and font policy exposed to both host apps and Flatpak:
  `Inter`, `Source Han Sans`, `Source Han Serif`, `Maple Mono NF CN`,
  `Twitter Color Emoji`, `Noto Color Emoji`, plus `fontconfig` rules
- theme stack exposed to both host apps and Flatpak:
  `Catppuccin-Macchiato`, `Papirus`, `Bibata-Modern-Ice`, `breeze`,
  `Darkly`, Plasma color scheme and look-and-feel assets
- input method static policy:
  `fcitx5` config, fcitx themes, Wanxiang baseline, Rime patch files, Flatpak
  IM env propagation
- desktop integration:
  XDG terminal registration, MIME defaults, XDG user dirs, portal policy,
  Flatpak global override

This flake is not the owner of:

- the login shell binary at `/usr/bin/zsh`
- the system desktop session itself: Plasma, compositor, display manager,
  polkit, DBus session bootstrap
- app-specific Flatpak overrides under `~/.local/share/flatpak/overrides/<app-id>`
- live credential-store entries and fallback runtime auth artifacts generated by
  apps, such as `gh` keyring items or `~/.config/gh/hosts.yml`
- DMS runtime output `~/.config/ghostty/config-dankcolors`
- DMS-generated Mango runtime files under `~/.config/mango/dms/`
- mutable Rime runtime state under `~/.local/share/fcitx5/rime/`
- manual extra fonts under `~/.local/share/fonts/` outside the `nix/` subtree

## Non-Nix Dependencies

The current setup still expects a small system-side base outside Nix.

Needed from the Arch repositories:

- `zsh`
  Your login shell still resolves to `/usr/bin/zsh`, so the system package must
  remain installed.
- `fcitx5`
  The fcitx runtime itself is intentionally system-owned.
- `fcitx5-gtk`
  Provides GTK input method modules for non-Nix desktop apps.
- `fcitx5-qt`
  Provides Qt input method plugins for non-Nix desktop apps.
- `fcitx5-rime`
  The Rime addon binary remains on the system side because fcitx runtime
  ownership stays there.
- `flatpak`
  Nix only manages the global override file; the Flatpak runtime itself remains
  system-managed.
- `xdg-desktop-portal-kde`
  The portal service runtime is still system-managed; Nix only owns the portal
  policy and per-user selection.
- `mangowc` or `mangowm-git`
  The compositor/session binary still lives on the host side for now. Nix owns
  the user config under `~/.config/mango`, not the login-session package.
- `dms-shell`
  The DMS runtime itself still lives on the host side even though Mango config
  is now repo-managed.
- `wlr-randr`
  Still used directly by the Mango config for monitor setup.
- `kservice`
  Provides `kbuildsycoca6`, which is called from the DMS startup path.
- `polkit-kde-agent`
  Still launched from the DMS startup path.
- `plasma-workspace`
  Provides `xembedsniproxy` for legacy tray bridge behavior in the Mango/DMS
  session.
- `pkgfile`
  Recommended for fast `pay-respects` package lookup on Arch. If it is missing,
  the shell can still fall back to `pacman -F` when the file database is
  available. Home Manager also installs a small compatibility wrapper so an
  uninitialized `pkgfile` cache does not break shell package suggestions.

Optional AUR packages:

- `paru` or `yay`
  Optional helper tools for AUR management. Nix does not depend on them.
- `zen-browser-bin`
  Optional if you want the current Mango browser hotkey target unchanged.

Not required by Nix itself, even if they still happen to be installed:

- `git`, `fd`, `ripgrep`
  Already provided by Home Manager. If pacman refuses to remove them, it is
  because some other system or AUR package still depends on them.
- old font/theme/icon packages from pacman/AUR
  These should be removable once no non-Nix package still requires them.

Shell package-repair policy:

- `f` / `fix` uses Arch-native package lookup on this machine.
- Long-lived shell tools that belong in your reproducible environment should
  still be added to the Home Manager flake instead of installed ad hoc through
  `fix`.
- `paru` remains a manual AUR workflow tool, not the default backend for
  `pay-respects`.

## Structure

- `flake.nix`: top-level Home Manager entrypoints.
- `home/default.nix`: shared module root.
- `home/modules/profile.nix`: base profile selection plus feature overrides.
- `home/modules/shell/`: shell behavior and CLI tool wiring.
- `home/modules/gui/`: fonts, GTK, Plasma, input method, portals, Flatpak, and
  graphics glue.
- `home/modules/ghostty.nix`, `fastfetch.nix`, `starship.nix`, `git.nix`,
  `gh.nix`, `xdg.nix`, `themes.nix`: tool-specific modules.
- `home/files/`: canonical config sources and binary assets that should remain
  in native file formats.
- `docs/`: local policy notes such as shortcut and auth guidance.
- `scripts/verify-shell-migration.sh`: post-switch verification.
- `scripts/cleanup-pacman-duplicates.sh`: pacman/AUR duplicate cleanup helper.
- `scripts/install-arch-runtime-deps.sh`: installs the small Arch-side runtime
  base that intentionally stays outside Nix.

## Profiles And Feature Overrides

The flake keeps three base profiles:

- `desktop`: full workstation stack.
- `shell`: shell stack plus fonts.
- `container`: shell stack only.

Those base profiles can be adjusted without cloning the whole module tree. The
switchboard lives in `home/modules/profile.nix`:

- `ahdg.profile`: choose the base profile.
- `ahdg.extraFeatures`: add feature flags on top of the base profile.
- `ahdg.disabledFeatures`: subtract feature flags from the base profile.

This is what the flake exports today:

- `ahdg`: full desktop profile.
- `ahdg-shell`: shell profile with fonts.
- `ahdg-container`: container profile without fonts.

Runtime metadata is written after activation:

- `~/.config/ahdg/profile`: resolved deployment label such as `desktop`,
  `shell-minimal`, or `container-fonts`.
- `~/.config/ahdg/base-profile`: the base profile before feature overrides.
- `~/.config/ahdg/enabled-features`: one enabled feature per line.

That metadata is what the verification script now uses, so custom feature mixes
can still be checked correctly.

The extra feature overrides stay available for future reuse, but they are no
longer exposed as separate everyday flake outputs.

## Design Rules

- Shell orchestration belongs in Nix because multiple tools need ordered init.
- App-native config files stay in native formats under `home/files/`.
- Static resources should come from nixpkgs when possible, not copied forks.
- Mutable theme outputs should stay writable when another tool owns them at
  runtime. `ghostty/config-dankcolors` is the main example.
- Flatpak-facing theme and font files should be materialized as regular files or
  directories, because sandboxed apps do not reliably follow `/nix/store`
  symlinks.
- Input-method static payloads should be split from runtime state. Nix owns the
  `fcitx5` config, theme assets, and Rime baseline files; `userdb`, `sync`, and
  deployment caches remain writable runtime state.
- Global Flatpak policy should be Nix-owned. Per-app Flatpak overrides should
  stay manual.
- KDE Plasma is the Qt settings authority here. `qt5ct` and `qt6ct` are treated
  as obsolete parallel config paths and are removed.
- Papirus is the single icon theme. Darkly is the Qt widget style layer.
  Catppuccin Macchiato Lavender remains the color/look-and-feel layer.

## Official Resource Policy

The goal is to minimize local vendored theme payloads. Current desktop assets
come from nixpkgs wherever an official package exists:

- `pkgs.catppuccin-kde`
- `pkgs.catppuccin-gtk`
- `pkgs.darkly`
- `pkgs.papirus-icon-theme`
- `pkgs.bibata-cursors`
- `pkgs.kdePackages.breeze-icons`
- `pkgs.catppuccin-fcitx5`
- font packages from nixpkgs
- official `amzxyz/rime_wanxiang` release archives for the Wanxiang base scheme
  payload
- pinned Wanxiang auxiliary assets copied under `home/assets/fcitx5/` when the
  upstream moving release channels (`dict-nightly`, `LTS`) need an exact local
  snapshot

Local files in `home/files/` are kept only for:

- app-native config files such as Ghostty, Fastfetch, Starship, and Zsh snippets
- app-native input-method config and Rime patch files
- small compatibility files such as `fontconfig/fonts.conf`
- binary assets such as Fastfetch logos
- default seeds for mutable runtime files

## Switch Commands

```bash
home-manager switch --flake ~/.config/nix#ahdg
home-manager switch --flake ~/.config/nix#ahdg-shell
home-manager switch --flake ~/.config/nix#ahdg-container
```

If `home-manager` is not installed globally:

```bash
nix run github:nix-community/home-manager -- switch --flake ~/.config/nix#ahdg -b pre-nix
```

To inspect an activation package first:

```bash
nix build ~/.config/nix#homeConfigurations.ahdg.activationPackage
```

To bootstrap the Arch-side runtime dependencies first:

```bash
~/.config/nix/scripts/install-arch-runtime-deps.sh
~/.config/nix/scripts/install-arch-runtime-deps.sh --apply
```

- Flatpak global override
- `xdg-terminals.list`

Keep using `home/files/` only for configs that are meaningfully easier to edit
in their native format or may need to stay writable for external tools.

## Intentional Manual State

Some files remain outside strict Nix ownership on purpose:

- `~/.config/ghostty/config-dankcolors`
  DMS still updates this file at runtime.
- `~/.local/share/flatpak/overrides/<app-id>`
  App-specific Flatpak overrides stay manual.
- `gh` keyring entries or fallback `~/.config/gh/hosts.yml`
  `gh` login remains local runtime state. The repo only records best practices
  for future backup/sync work.
- `~/.local/share/fonts/`
  The `nix/` subtree is Nix-managed. The runtime `custom/` subtree is copied
  from `~/.config/nix/home/assets/fonts/custom/`, which is the canonical place
  for custom fonts you want to carry with this repo.
- `~/.local/share/fcitx5/rime/build/`
- `~/.local/share/fcitx5/rime/sync/`
- `~/.local/share/fcitx5/rime/*.userdb/`
- `~/.local/share/fcitx5/rime/user.yaml`
- `~/.local/share/fcitx5/rime/installation.yaml`
  These are live Rime runtime artifacts and should remain writable.

## Runtime Expectations

After a successful switch:

- `~/.zshenv`, `~/.config/zsh/.zshenv`, and `~/.config/zsh/.zshrc` are Home
  Manager symlinks.
- `~/.config/ghostty/config` is a Home Manager symlink when Ghostty is enabled.
- `~/.config/ghostty/config-dankcolors` is a writable regular file when theme
  runtime support is enabled.
- `~/.config/fcitx5/config`, `profile`, and `conf/*.conf` are regular files.
- `~/.gtkrc-2.0` is a Home Manager symlink.
- `~/.config/fontconfig/fonts.conf` is a regular file, not a store symlink.
- `~/.local/share/fonts/custom/` is a regular directory copied from
  `~/.config/nix/home/assets/fonts/custom/`.
- GTK themes, fcitx themes, icon themes, and Plasma color-scheme copies exposed
  to Flatpak are regular files or directories, not store symlinks.
- `~/.local/share/fcitx5/rime/` contains a Nix-refreshed Wanxiang baseline plus
  writable runtime subtrees such as `build/`, `sync/`, and `*.userdb/`.
- `~/.config/gtk-3.0/gtk.css` and `~/.config/gtk-3.0/dank-colors.css` are gone.
- `~/.config/autostart/org.fcitx.Fcitx5.desktop` should not exist. The system
  fcitx desktop entry is intentionally left unmasked.
- `~/.config/environment.d/90-dms.conf` is gone.
- `~/.gitconfig` exists as a Home Manager managed compatibility entrypoint and
  should resolve the same global author identity as `~/.config/git/config`.
- `~/.config/qt5ct` and `~/.config/qt6ct` are gone.

## Package Cleanup

Use the cleanup helper in dry-run mode first. It is reverse-dependency aware and
only proposes pacman removals that are currently safe on this machine:

```bash
~/.config/nix/scripts/cleanup-pacman-duplicates.sh
~/.config/nix/scripts/cleanup-pacman-duplicates.sh --apply
```

At the moment, most obvious duplicates such as `git`, `fd`, and `ripgrep` are
still pulled in by other pacman/AUR packages, so they are intentionally not
removed. The current setup usually only leaves small leaf packages such as
`fcitx5-configtool` as immediate cleanup candidates.

Intentionally kept outside that cleanup:

- `fcitx5`, `fcitx5-gtk`, `fcitx5-qt`, `fcitx5-rime`, `librime`, `librime-data`,
  because the fcitx runtime stays on the system side
- `zsh`, because your login shell still points at `/usr/bin/zsh`
- `dms-shell`, because your live Ghostty color overlay is still generated by DMS

To install or re-check the Arch-side runtime base itself:

```bash
~/.config/nix/scripts/install-arch-runtime-deps.sh
~/.config/nix/scripts/install-arch-runtime-deps.sh --apply
~/.config/nix/scripts/install-arch-runtime-deps.sh --apply --with-recommended
```

## Validation

Run once after switching and once after reboot:

```bash
~/.config/nix/scripts/verify-shell-migration.sh
```

Or target a specific deployment explicitly:

```bash
~/.config/nix/scripts/verify-shell-migration.sh shell
~/.config/nix/scripts/verify-shell-migration.sh container
```

The verification script now decides most checks from
`~/.config/ahdg/enabled-features`, so custom feature mixes remain valid without
rewriting the script.
